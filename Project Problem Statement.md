##### **Problem Statement:**



##### **Introductory ATM programs often model a single hard-coded account. That design cannot show how a real kiosk handles many cards, how a customer switches accounts, or how data survives after the program closes. Students also rarely practise PIN retries, insufficient-funds handling, or audit-style mini-statements.**

##### **The problem addressed by this project is: design and implement a console ATM that supports multiple independent cards, authenticates the holder with a PIN (maximum three attempts), performs deposit and withdrawal with validation, records a compact transaction history, and stores the entire card collection in a file so the next run continues from the last saved state.**
